# AGENTS.md

This document provides context for AI agents working with this repository.

## Project Overview

This is a TypeScript project for AI-powered image and video generation using multiple API providers:

- **OpenRouter API**: Gateway providing access to various image generation models (Gemini, Flux, Seedream, Riverflow, GPT-5 Image)
- **XAI (Grok) API**: Direct access to Grok's image generation, image editing, and video generation capabilities

## Project Structure

### Core Scripts

| Script | Description | API Pattern |
|--------|-------------|-------------|
| `list_models.ts` | List image-capable models on OpenRouter | Axios + raw HTTP |
| `generate_image.ts` | Benchmark: generate images across multiple OpenRouter models | OpenRouter SDK |
| `generate_video.ts` | Video generation via OpenRouter's Veo model | Raw fetch (polling) |
| `grok_generate_image.ts` | Single image generation with Grok | Vercel AI SDK (`generateImage`) |
| `grok_generate_video.ts` | Video generation with Grok (image-to-video) | Vercel AI SDK (`experimental_generateVideo`) |
| `grok_edit_image.ts` | Image editing with Grok (instruct-based edits) | Raw fetch to `api.x.ai` |
| `grok_expressions.ts` | Batch expression variations on a base image | Raw fetch to `api.x.ai` |

## TypeScript Configuration

- **Module system**: ES modules (`"type": "module"` in package.json, `module: "nodenext"`)
- **Target**: `esnext`
- **Strict mode**: Enabled (`strict: true`)
- **Enforced patterns**: `verbatimModuleSyntax`, `isolatedModules`, `noUncheckedSideEffectImports`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`
- **Note**: `types: []` is set in tsconfig, meaning no ambient types are auto-included. `@types/node` must be imported explicitly where needed.

## API Patterns in Use

This project mixes three distinct API approaches. Keep them straight when editing:

### 1. OpenRouter SDK (`@openrouter/sdk`)
Used in: `generate_image.ts`

```ts
const openRouter = new OpenRouter({ apiKey: process.env.OPENROUTER_API_KEY! });
const result = await openRouter.chat.send({ chatGenerationParams: { ... } });
```

### 2. Vercel AI SDK (`ai` + `@ai-sdk/xai`)
Used in: `grok_generate_image.ts`, `grok_generate_video.ts`

```ts
const xai = createXai({ apiKey: process.env.XAI_API_KEY! });
const { image } = await generateImage({ model: xai.image("..."), ... });
const { video } = await generateVideo({ model: xai.video("..."), ... });
```

### 3. Raw HTTP fetch
Used in: `generate_video.ts` (OpenRouter video endpoint), `grok_edit_image.ts`, `grok_expressions.ts`, `list_models.ts` (axios)

Direct requests to `https://openrouter.ai/api/v1/videos` or `https://api.x.ai/v1/images/edits`.

## Key Implementation Details

### Image Generation

- Images returned as base64 strings within data URIs (`data:image/png;base64,...`)
- Decoded to `Buffer` and written as PNG files
- Supports custom aspect ratios (commonly `9:16` portrait or `16:9` landscape)
- OpenRouter: use `modalities: ['image']` and `imageConfig` for aspect ratio/size control

### Video Generation

- **OpenRouter (Veo)**: Submit job → poll `polling_url` every 30s → download from `unsigned_urls[0]` when `status === 'completed'`
- **Grok**: Uses `experimental_generateVideo` which handles download automatically; returns `video.uint8Array`

### Image Editing (Grok)

- Source image read from disk, converted to base64 data URI
- POST to `https://api.x.ai/v1/images/edits` with `model: "grok-imagine-image-quality"` (edits) or `model: "grok-imagine-image"` (expressions)
- Response contains a URL; download separately and save

### Error Handling Pattern

- Try-catch blocks with continuation on failure (`generate_image.ts`, `grok_expressions.ts`)
- Some scripts use `process.exit(1)` on error (`grok_edit_image.ts`, `generate_video.ts`)
- Error details logged via `console.error` with response data or message

## Notes for AI Agents

1. **Ignore binary output files** — The repo contains many generated images (PNG, JPG, JPEG) and videos (MP4). Skip these during code analysis. Focus exclusively on `.ts` files.
2. **Do not scan `node_modules/`** — Standard Node.js dependencies.
3. **API keys** — Stored in `.env` (gitignored). Never hardcode keys in source files.
4. **Module system** — ES modules only. Use `import`/`export`, not `require`/`module.exports`. All top-level `await` is valid (modules only).
5. **No build step** — Scripts are run directly with `tsx`. There is no `dist/` or `outDir`.
6. **Multiple API patterns** — Before editing, identify which of the three patterns the file uses (see "API Patterns in Use" above) and stay consistent with it.
7. **dotenv loading** — Two styles coexist: `import 'dotenv/config'` (side-effect import) and `dotenv.config()` (explicit call). Both work; match the existing style of the file you're editing.
8. **Output directories** — Generated content lands in `benchmark_output/`, `expressions_output/`, or `grok output/`. Some are gitignored, some are not. Don't rely on gitignore for cleanup.
